Role Name
=========

The deploy_pxe_boot_media role publishes PXE boot media (already generated by the create_agent_install_media role/playbook with `boot_method: pxe`) for real network boot: kernel, initrd, and rootfs all go on the bastion's httpd (matching `boot-artifacts/agent.x86_64.ipxe`, which the installer itself generates -- see `templates/grub-netboot.cfg.j2`), and a GRUB netboot config is written for each of the cluster's master nodes so different clusters' nodes automatically boot their own image. TFTP only serves the shim/grub bootloader chain and these per-MAC configs, not the boot artifacts themselves.

This handles only per-cluster, run-every-time work. The one-time, bastion-wide Secure Boot bootloader chain (shim -> grubx64.efi) that this depends on lives in the separate `pxe_bootloader_setup` role -- see its README for why that's split out.

This is also a separate role/playbook from create_agent_install_media on purpose -- generating boot media (which just needs `openshift-install` and writes into this repo's own `output/` directory) and deploying it (which needs root, and touches system paths like `/var/lib/tftpboot` and `/var/www/html` on the bastion) are different operations with different blast radii.

Requirements
------------

- The bastion must already have `tftp-server` and `httpd` installed and running (see `bastion_setup.yaml`).
- `pxe_bootloader_setup.yaml` must already have been run once on this bastion (this role fails fast with a clear message if not).
- PXE boot media must already exist at `playbooks/output/<cluster_name>/work/boot-artifacts/` -- generate it with:
  ```bash
  ansible-playbook playbooks/create_agent_install_media.yaml -e "cluster_name=<cluster_name> boot_method=pxe"
  ```

Role Variables
--------------

- `tftp_root` (default `/var/lib/tftpboot`), `http_docroot` (default `/var/www/html`) -- see `defaults/main.yml`.
- `bastion_ip` -- shared across clusters, defined in `playbooks/group_vars/all/bastion.yml`.
- Per-cluster `masterN_hostname`/`masterN_mac` from `playbooks/group_vars/<cluster_name>/vars.yml` -- used to generate one GRUB config per master, keyed by MAC address.

How node routing works
-----------------------

GRUB's network boot natively searches for `grub.cfg-01-<mac>` (dashes, lowercase) before falling back to a generic `grub.cfg`. Each master's config file is written independently into `tftp_root`, so separate per-cluster deploy runs never need to coordinate or share a single file -- a node's own MAC is what determines which cluster's kernel/initrd/rootfs it boots.

What this role does NOT do
---------------------------

It does not touch your DHCP server. DHCP's "Next Server" must point at the bastion, and "UEFI 64 bit File Name" must be `shimx64.efi` (root-relative, no path) -- both administered separately by whoever administers DHCP.

Example Playbook
----------------

```yaml
- name: Deploy OpenShift Agent Installer PXE boot media
  hosts: localhost
  connection: local
  become: true

  roles:
    - deploy_pxe_boot_media
```

```bash
ansible-playbook playbooks/pxe_bootloader_setup.yaml   # once, ever
ansible-playbook playbooks/deploy_pxe_boot_media.yaml -e "cluster_name=<cluster_name>"   # every time
```
